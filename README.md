# jangrye.keywordegg.com

전국 화장시설·장례식장의 **요금**과 **위치·가는 길·시설 정보**를 한 화면에
보여주는 사이트. vet·medifee·yoyang 과 같은 스택(Next.js + Supabase +
Cloudflare Workers)과 같은 UI 스킨을 쓴다.

---

## 이 사이트가 하는 말

**같은 화장장인데 관내 5만원, 관외 100만원이다.**

화장시설은 대부분 지자체가 세운 공설이다. 그 지역 주민의 세금으로 지었으니
주민에게는 싸게, 다른 지역 주민에게는 원가에 가깝게 받는다. 그 폭이 조례로
정해지고 지자체마다 다르다 — 전국 중간값으로 **10배**, 최대 **20배** 차이다.

그리고 화장시설이 있는 시군구가 **247곳 중 59곳뿐**이다. 나머지 지역 주민은
이웃 시군구로 가면서 관외 요금을 낸다. 이걸 미리 아는 것이 이 사이트의 쓸모다.

**가격만 보여주지 않는다.** 값을 알아도 어디로 가야 할지 모르면 소용이 없다.
주소·전화·대중교통·자차 경로·주차 대수·편의시설·사진을 함께 둔다.

## URL 구조

경로가 한 단계다. `app/[slug]/page.tsx` 하나가 다섯 종류의 화면을 나눠 맡는다.

| 경로 | 화면 | 정의 위치 |
|---|---|---|
| `/` | 홈 | `app/page.tsx` |
| `/화장시설` `/장례식장` | 종류별 허브 | `GROUPS` (`lib/facilities.ts`) |
| `/지역` | 지역 허브 | `REGION_HUB_SLUG` (`lib/regions.ts`) |
| `/서울` | 시도 상세 | `SIDOS` (`lib/regions.ts`) |
| `/서울-서초구` | 시군구 상세 | `jangrye_regions.region_slug` |
| `/서울추모공원-4000000056` | 시설 상세 | `jangrye_facilities.slug` |
| `/about` `/contact` `/privacy` `/terms` | 안내 페이지 | 각 디렉터리 |

슬러그는 한글을 쓴다. **시설 슬러그와 지역 슬러그를 가르는 기준은 끝이 6자리
이상 숫자인지다** (`서울추모공원-4000000056` vs `서울-서초구`). 시설명에 숫자가
들어가도 코드가 항상 뒤에 붙으므로 충돌하지 않는다.

조회는 이름이 아니라 **슬러그 끝의 시설코드**로 한다(`codeFromSlug`). 그래서
다음 갱신에서 시설명이 바뀌어도 예전 URL 이 열리고 canonical 만 새 주소를
가리킨다.

## 데이터

보건복지부 **e하늘 장사정보시스템** <https://www.15774129.go.kr>

2010년부터 운영되는 정부 포털이고, 시설이 직접 위치·시설정보·가격을 등록한다.
전국 장사시설 2,625곳이 있다.

```bash
npm run probe:facilities      # 시설 하나만 받아 모양 확인
npm run import:facilities     # 1단계 전량 수집 + 적재 (약 15분)
npm run import:facilities -- --dry-run
npm run load:facilities       # 받아 둔 data/raw/facilities.json 만 적재
npm run import:facilities -- --all   # 5종 전부 (봉안·묘지·자연장지까지)
```

**공공데이터포털에는 전국 장사시설 요금 데이터셋이 없다.** 지자체 단위 장례식장
목록만 파편적으로 있다. 그래서 e하늘 조회 화면이 쓰는 내부 JSON 두 개를 읽는다.

```
POST /portal/fnlfac/fac_list.ajax    시설 목록
POST /portal/fnlfac/price_info.ajax  시설 하나의 가격 전부
```

> 공개 API 가 아니다. `robots.txt` 는 없지만(404) 규격이 예고 없이 바뀔 수 있어
> 응답을 검증하고 요청 간격을 250ms 로 둔다.

### 1단계로 올린 것

| 종류 | 건수 | 시설당 가격 행 | 가격 기준 2024년 이후 |
|---|---:|---:|---:|
| 장례식장 | 1,084 | ~100 | 68% |
| 화장시설 | 62 | ~20 | 42% |

시설 1,146곳 · 시군구 247곳 · 사진 있는 곳 1,143(99.7%) · 교통안내 715곳 ·
가격 행 110,620.

**봉안시설(711)·묘지(503)·자연장지(265)는 아직 안 올렸다.** 가격 기준일이
오래된 곳이 많아(묘지는 2024년 이후가 15%뿐) 신뢰 표시 설계가 먼저 필요하다.

## 화장료를 갈라내는 규칙 — 이 프로젝트에서 가장 손이 많이 간 부분

원본에 `inneradultamt`(관내 대인) 같은 **정형 컬럼이 있지만 62곳 중 9곳(15%)만
채워져 있어 쓸 수 없다.** 실제 값은 `hallRent` 행에 있고 관내/관외 구분이
`rentcontent` 자유 텍스트에 들어 있다. 386종이지만 구조는 일정하다.

```
일반(대인)-일반(관내)
일반(소인)-국민기초생활보장수급자(관외)
개장유골-일반(인접/준관내)
일반(대인)-일반(봉화)              ← 지역명을 직접 쓴 것
관내-보훈대상자(일반(대인))          ← 순서가 뒤바뀐 것
```

`scripts/jangrye-codes.mjs` 가 이걸 **(대상 × 지역구분 × 자격)** 세 축으로
가른다. 확보율은 대인 관내 54/62(87%) · 관외 53/62(85%).

### 여기서 두 번 틀렸다 — 같은 함정을 다시 밟지 말 것

**① `행려(대인)` 을 대인으로 분류했다.** 행려병자는 지자체가 처리하는 것이라
요금이 0원인데, 규칙이 "일반" 패턴을 먼저 봐서 일반 대인 요금으로 들어갔다.
화면에 **"관내 무료"** 라고 나왔다. → 특수 대상(태아·개장유골·무연고·행려)을
**먼저** 걸러낸 뒤에 대인/소인을 본다.

**② `보훈대상자` 를 감면 자격으로 못 잡았다.** `국가유공자` 만 보고 있었다.
역시 0원이라 같은 증상이 났다. → `보훈` 도 함께 잡는다.

그리고 안전장치를 두 곳에 걸었다. **대표값을 고를 때 0원은 뒤로 민다** —
0보다 큰 값이 하나라도 있으면 그중 최저를 쓰고, 0원만 있을 때만 무료로 둔다.
화면(`feeMap`)과 DB 집계(`refresh_jangrye_aggregates`) **양쪽 다** 걸어야 한다.
한쪽만 고치면 지역 집계가 여전히 0원으로 남는다.

지금 남은 0원 일반 요금은 **국립소록도병원화장장 한 곳**이고 그건 실제로 무료다.

## 오래된 가격을 다루는 방식

시설이 가격을 등록한 시점이 제각각이다. 2015년에 멈춘 곳도 있다.

- 시설 상세·목록에 `price_date` 를 **항상** 노출한다
- `STALE_BEFORE`(2023-01-01) 보다 오래되면 **'요금 오래됨'** 을 붙인다
- 오래된 값은 **순위·중간값 계산에서 뺀다** (허브의 "차이가 큰 곳", 전국 시세)

medifee 에서 2015년 가격 데이터를 통째로 버렸던 것과 같은 문제인데, 화장료·묘지
사용료는 조례로 정해져 잘 안 바뀌므로 여기서는 버리지 않고 표시하는 쪽을 골랐다.

## 품목명은 비교하지 않는다

장례식장 품목은 시설이 직접 입력해서 138종 분류에 최다가 `기타 › 기타류` 다.
같은 관이 "오동집성 1.0" 과 "오동나무관(특)" 으로 흩어져 있다. 그래서 **코드값인
`tier1`/`tier2` 수준까지만 묶고** 세부 품목은 나열만 한다. 시설끼리 품목 단위로
견주는 화면은 만들지 않는다.

원본이 계산해 둔 관내·전국 평균(`avg_in`·`avg_all`)은 장례식장에만 절반쯤
채워져 있어, 있을 때만 표에 함께 보여준다.

## 테이블

| 테이블 | 내용 |
|---|---|
| `jangrye_facilities` | 시설 마스터 1,146행. 위치·교통·편의·사진 포함 |
| `jangrye_cremation_fees` | 화장료 1,049행 (대상 × 지역구분 × 자격) |
| `jangrye_prices` | 빈소 임대료·서비스·장사용품 110,620행 |
| `jangrye_regions` | 시군구 집계 247행 |

집계는 매 요청 계산하지 않고 `refresh_jangrye_aggregates()` 로 적재 후 한 번에
다시 만든다. 적재 스크립트가 마지막에 호출한다.

> 이 Supabase 프로젝트는 `pg_safeupdate` 가 켜져 있어 **WHERE 없는 DELETE 가
> 막힌다.** 집계 함수 안에서 `delete ... where true` 를 쓰는 이유다.

## 사진

시설당 최대 12장이 있고 1,143곳(99.7%)에 붙어 있다. **e하늘 서버 경로를 그대로
참조하고 우리 쪽으로 복사하지 않는다.** `next/image` 최적화도 걸지 않았다 —
워커에서 원격 도메인 설정이 필요하고 이미지가 끊길 때 빈 칸이 남는다.

복사할지는 저작권을 확인한 뒤 결정할 것.

## 광고 배치 — 이 사이트만 다르게 한다

유족이 상중에 보는 화면이다. **요금표 사이에 광고를 끼우지 않는다.**

- `top`(상단) — 도입부 다음, 숫자가 나오기 전
- `middle`(CTA) — 요금과 장소 정보를 **모두 보여준 다음**
- `home`(글지역) — 홈·허브 목록 위
- `bottom`(h2) — 본문 맨 끝

퍼블리셔 ID 는 keywordegg 계열과 같은 계정이고 슬롯만 이 사이트 것을 쓴다.

## 시작하기

```bash
# 1) Supabase SQL 편집기에서 마이그레이션 실행
#    supabase/migrations/001_create_jangrye_tables.sql
#    supabase/migrations/002_aggregate_ignore_zero_fees.sql

# 2) .env.example 을 .env.local 로 복사해 채운다
#    Supabase 는 keywordegg 계열과 같은 프로젝트를 쓴다

# 3) 데이터 적재 (약 15분)
npm run import:facilities

# 4) 개발 서버
npm run dev
```

**수집에는 API 키가 필요 없다.** 원본이 공공데이터포털이 아니라 e하늘이고
인증이 걸려 있지 않다.

## 배포

```bash
npm run cf:deploy
```

배포 후 Cloudflare 대시보드에서 커스텀 도메인 `jangrye.keywordegg.com` 을 연결한다.
